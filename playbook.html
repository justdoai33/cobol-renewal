Step-by-step guide for using this framework to reverse engineer and modernise a COBOL/JCL batch system. Follow this sequence for each new project.

Before You Start

You need:

  • Source artefacts extracted from the mainframe (JCL, COBOL programs, copybooks, sort controls)
  • Python 3.10+ installed
  • An AI-powered development environment
  • A named workspace directory for the project

You don't need:

  • Prior documentation of the system (that's what this framework produces)
  • Deep COBOL expertise (the AI does the reading — you validate the output)
  • The target implementation language decided upfront (decide after analysis)

The Steps

  1. Initialise the Project Run the init script — this creates the project structure, copies framework files, and runs pre-processing tools automatically. If source files aren't available yet, initialise empty and add them later.

    Output: A git-versioned project with steering, skills, templates, tools, and metadata.
  2. Pre-Process Source Automated parsers extract metadata from JCL (dependencies, step flow), copybooks (field definitions with byte offsets), and sort controls (key specifications). Reports any missing artefacts.

    Gate: Do not proceed until all referenced artefacts are available or explicitly acknowledged as unavailable.
  3. Reverse Engineer The AI reads all source artefacts — JCL first to understand job flow, then COBOL, copybooks, and sort controls. Produces a narrative analysis and generates the project-specific context.

    Your role: Confirm environment variables, answer clarifying questions, identify the PoC component.
  4. Generate Knowledge Base (Wiki) The AI produces structured documents: system overview, program inventory, data dictionary, file catalogue, job map, and domain glossary.

    Your role: Review each document for accuracy. Flag items you know to be incorrect.
  5. Generate Component Specifications For your chosen component, produces: BRS (EARS business rules), FRS (functional requirements), TDD (technical design in target language), GAPS (open questions).

    Your role: Validate BRS against business knowledge. Choose target language. Review TDD for architectural fit.
  6. Validate Automated checks: all 9 sections present, traceability chain unbroken (COBOL → BRS → FRS → TDD), cross-references consistent, no unresolved markers.
  7. Resolve Gaps Work through open questions with business SMEs. HIGH-priority gaps must be resolved before implementation. Each resolution updates the affected spec documents.
  8. Implement Build from the TDD. Run equivalence testing — compare output byte-for-byte against COBOL output. Fix differences. Get stakeholder sign-off.
  9. Expand Repeat steps 5–8 for each additional component. The wiki and context already exist — each new component only needs its spec set. ~2 hours per component.
