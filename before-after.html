The Source: Raw COBOL (208 lines)

No documentation. No comments explaining business intent. Commented-out code with unknown significance. A developer unfamiliar with this system would need days to understand what it does — and still might get it wrong.

BEFORE — Raw COBOL (excerpt)
000010 IDENTIFICATION DIVISION.
000030 PROGRAM-ID.         MIP1293.
000040 AUTHOR.             ROGER MOSS.
000400* COMPARE THE BILLING FILE AGAINST THE MONTHLY ACCUMULATIVE
000400* SECURITY. IF ALREADY FOUND THEN REJECT ELSE WILL ABEND
000400* ON SYBASE WITH DUPS.

       01     W-EOF-MAST          PIC X VALUE  'N'.
       01     W-EOF-CHG           PIC X VALUE  'N'.
       01  W-COMPARE.
           05 W-COMPARE-MAST  PIC X(17).
           05 W-COMPARE-CHG   PIC X(17).

       A-TOP SECTION.
           OPEN INPUT INMAST
           OPEN INPUT INCHG.
           OPEN OUTPUT OUTMAST.
           OPEN OUTPUT OUTREJ.
           READ INMAST AT END
                       MOVE 'INSERT    ' TO WS-DUMP-ACTION
                       MOVE 9999         TO WS-DUMP-CODE
                       ADD 1             TO WS-DUMP.
           MOVE INMAST-REC(3:17) TO W-COMPARE-MAST.
           READ INCHG AT END MOVE 'Y' TO W-EOF-CHG.
           PERFORM B-MAIN UNTIL W-EOF-MAST = 'Y'
                            AND W-EOF-CHG = 'Y'.

       B-MAIN SECTION.
       B-FIND.
           IF W-COMPARE-MAST < W-COMPARE-CHG
              MOVE INMAST-REC TO OUTMAST-REC
      *       WRITE OUTMAST-REC
              PERFORM Z-READ-MAST
              GO TO B-EXIT.
           IF W-COMPARE-MAST > W-COMPARE-CHG
              MOVE INCHG-REC  TO OUTMAST-REC
              WRITE OUTMAST-REC
              PERFORM Z-READ-CHG
              GO TO B-EXIT.
           IF W-COMPARE-MAST = W-COMPARE-CHG
              MOVE INCHG-REC  TO OUTREJ-REC
              WRITE OUTREJ-REC
              PERFORM Z-READ-MAST
              PERFORM Z-READ-CHG
              GO TO B-EXIT.
AFTER — Extracted Business Rules
BR-001: The billing deduplication process
SHALL process records in ascending account
key sequence.

BR-003: WHEN an account key in the daily
billing file matches an account key in the
monthly security file, the system SHALL
classify that daily billing record as a
duplicate.

BR-004: WHEN a daily billing record is
classified as a duplicate, the system SHALL
write it to the duplicate rejection file.

BR-006: The account key used for comparison
SHALL be a 17-byte value comprising the
company identifier, product code, and account
number fields, located at bytes 3–19.

BR-007: WHEN an account key exists in the
daily billing file but does not exist in
the monthly security file, the system SHALL
classify that record as a new billing record.

BR-009: [PARTIAL — see GAPS G-002]
WHEN an account key exists in the monthly
security file but does not exist in the daily
billing file, the system SHALL [determine
correct disposition — see gap].

Key Observations

  • The commented-out WRITE was caught — this is a critical ambiguity that affects output correctness. A human reading the code might miss it or assume it's debug cleanup. The framework flagged it as the highest-priority open question.
  • Business rules are technology-agnostic — BR-003 says "WHEN an account key matches, classify as duplicate." It doesn't say "IF W-COMPARE-MAST = W-COMPARE-CHG." This means the same rules drive Python, Java, or Go implementations.
  • Every rule traces back to a source line — BR-003 comes from MIP1293.cob line 01810. When a stakeholder asks "why does the new system reject this record?", the answer chain is complete.
  • Edge cases are explicit — what happens when the security file is empty? When the daily file is empty? When both are empty? The COBOL handles some of these implicitly (or not at all). The specification forces explicit decisions.
